# tasks.hx

Задачи проекта для Helix + Steel: список в стиле VS Code `Run Task` с поиском,
и панель вывода с живым логом.

Запуск задач вынесен в маленький нативный хелпер `hx-task` (как `hx-term` в
`terminal/`): он владеет pty и группой процессов, поэтому умеет корректно
убивать всё дерево, отдавать код выхода и не оставляет сирот.

## Сборка

```sh
cd ~/.config/helix/tasks && make      # gcc + libutil, ничего больше не нужно
```

Без `bin/hx-task` плагин не запускает задачи и подсказывает собрать хелпер.
Путь можно переопределить переменной `HELIX_TASKS_HELPER`.

## Файл задач

В корне проекта (workspace) — `.helix/tasks.toml`. Если его нет, плагин
смотрит `tasks.toml` в корне (полезно, чтобы не трогать `.helix/`, см. ниже).

```toml
# комментарии разрешены
[task.run]
cmd = "cargo run"
description = "запустить приложение"   # необязательно
cwd = "crates/app"                     # необязательно, относительно корня

[task.test]
cmd = 'cargo test -- --nocapture'
description = "прогнать тесты"

[task.build]
cmd = ["cargo", "build", "--workspace"] # массив склеивается через пробел
```

Поддерживается: `#`-комментарии, `"..."` со стандартными экранированиями,
`'...'` как литеральная строка, массивы строк. Секции, кроме `[task.<name>]`,
игнорируются вместе с ключами. Задача без `cmd` отбрасывается. Порядок задач
в окне — по алфавиту, но совпадения с запросом поднимаются наверх.

## Команды

| команда | что делает |
|---|---|
| `:tasks-toggle` | открыть/закрыть окно задач по центру (в `init.scm` повешено на `space k`) |
| `:tasks-output` | открыть/закрыть панель вывода текущей или последней задачи |
| `:tasks-reload` | перечитать `tasks.toml` и показать, что нашлось |

## Клавиши

**Пикер:** печатаешь — фильтр (подстрока, а если не нашлось — fuzzy по имени,
плюс поиск по `cmd`/`description`); `Up`/`Down` или `Ctrl-p`/`Ctrl-n` — выбор;
`PgUp`/`PgDn`; `Enter` — запустить (или показать вывод, если задача уже идёт);
`Ctrl-u` — очистить запрос; `Esc` — закрыть.

**Панель вывода:** `Esc` — закрыть (задача продолжает работать);
`Ctrl-k` — убить всё дерево процессов (`SIGTERM`, через 400 мс `SIGKILL`);
`r` — перезапустить (когда задача не идёт);
`Up`/`Down`/`PgUp`/`PgDn`/`Home`/`End` — скролл. Пока не отскроллил вверх —
вывод автоматически листается за концом.

## Как запускается

`hx-task` запускает `sh -c "<cmd>"` в pty в корне workspace (или в `cwd` из
задачи). Что это даёт:

- `isatty` → программы включают цвет и прогресс-бары;
- прогресс-бар, перерисовываемый через `\r`, обновляет одну строку, а не
  засоряет лог;
- `Ctrl-k` бьёт по группе процессов (`sh`, `make`, `sleep`, сервер);
- код выхода (или «убит сигналом N») показывается в панели и статуслайне;
- при выходе из helix или падении плагина хелпер получает EOF, убивает группу
  и уходит — задачи не остаются сиротами.

Одновременно идёт одна задача: запуск новой закрывает stdin предыдущего
хелпера, и тот гасит своё дерево.

## Ограничения

- ANSI-последовательности пока вырезаются: цвета в панели не рисуются.
- `Ctrl-C` в панели не форвардится (Esc занят закрытием), для остановки —
  `Ctrl-k` (`SIGTERM` → `SIGKILL`).
- Хелпер — POSIX/Linux (forkpty, setsid), сборка требует `gcc` и `libutil`.

## Про workspace trust

В этом форке helix хеширует **все** файлы под `.helix/` для workspace trust.
Если проект уже был помечен доверенным (`:workspace-trust`), то после
добавления/правки `.helix/tasks.toml` он станет `Stale` и локальный
`.helix/helix.scm` перестанет грузиться до повторного `:workspace-trust`.
Если это мешает — держи `tasks.toml` в корне проекта (плагин его тоже читает).
